= Modern .NET build

All maintained .NET projects use SDK-style project files, target both .NET 8
and .NET 10, and stay beside their source trees. The migration does not
maintain a duplicate source tree or the former Waf build system.

== Requirements

Install a .NET 8 or .NET 10 SDK and CMake 3.20 or newer. Every maintained project multi-targets
`net8.0` and `net10.0`; the Windows GUI projects use `net8.0-windows` and
`net10.0-windows`. `build/install.sh` prefers the .NET 10 SDK and falls back to
.NET 8, publishing the matching target. Building every target at once requires
the .NET 10 SDK.

== Build

From the repository root:

[source,shell]
----
dotnet build Peach.Build.csproj --configuration Release
----

The aggregate project builds the portable core, Pro runtime and command-line
tools, tests, bundled third-party .NET sources, Unix trampoline, and LLM
validation assemblies. On Windows it also includes PeachValidator and
PeachXmlGenerator.

Individual projects can be built or run from their original directories:

[source,shell]
----
dotnet run --project pro/Peach/Peach.csproj -- --help
dotnet run --project core/Minset/PeachMinset.csproj -- --help
dotnet test core/Test/Peach.Core.Test.csproj --configuration Release
dotnet test pro/Test/Core/Peach.Pro.Test.csproj --configuration Release
----

== Minset native coverage

`PeachMinset` uses the native Intel Pin tool under `core/BasicBlocks` when it
collects coverage traces. The migration preserves the former layout: extract a
compatible Pin kit under any direct child directory of `3rdParty/pin/`.
MSBuild discovers it automatically and copies its
runtime and binaries to the published `pin/` directory. Both native Pin tools,
`bblocks` and `cedge`, are built automatically. CMake is the common build
entry point; the Intel Pin kit's supported Makefile rules remain the compiler
backend for those two Pin tools.

[source,shell]
----
dotnet build Peach.Build.csproj --configuration Release
./build/install.sh
----

== Migrated scope

* Core PIT parsing, cracking, data models, relations, fixups, scripting, state
  models, fuzzing engine, mutation strategies, publishers, and agents
* Pro analyzers, fixups, mutators, strategies, publishers, storage, monitors,
  licensing/job runtime, and command-line executables
* Linux and macOS implementations plus portable Windows implementations
* LLM core and all four validation assemblies
* The bundled Bouncy Castle, Google CityHash, and Managed ADB source trees
* CMake-built native test fixtures for CrashTest, CrashableServer, and
  CrashingFileConsumer, plus direct Unix process launching without Mono's
  debugger agent
* Cross-platform code-page registration, modern .NET-compatible deep cloning, and
  cooperative cancellation in place of unsupported thread termination

== Remaining compatibility boundaries

The following features are intentionally excluded from the modern .NET build
until they can be redesigned around supported APIs:

* `pro/WebApi2`: classic ASP.NET/System.Web, OWIN, and Nancy hosting
* `AgentTcpRemoting` and the Unix trampoline IPC mode: .NET Remoting
* Windows COM publisher/container
* The legacy REST channel implemented on SocketHttpListener

Peach and PeachService run without the old embedded Web UI. Several legacy
packages are still restored through .NET Framework compatibility assets; their
replacement is follow-up dependency work rather than a directory migration.

Linux monitor integration tests additionally require host privileges, GDB, and
the Peach `exploitable` extension. They compile on both target frameworks but
cannot all pass in an unprivileged container or sandbox.
